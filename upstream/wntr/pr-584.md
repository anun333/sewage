**Title:** Raise an error naming the CPU when the Linux EPANET library can't load (#584)

## Summary

Fixes #584. The EPANET libraries included for Linux are built for x86-64 only, and `wntr/epanet/toolkit.py` loads `libepanet/linux-x64/libepanet22.so` on every Linux. On aarch64 the load fails with

```
OSError: .../wntr/epanet/libepanet/linux-x64/libepanet22.so: cannot open shared object file: No such file or directory
```

although the file is there.

This PR adds `_check_linux_machine()` to `toolkit.py`. `ENepanet` and `MSXepanet` call it before loading a library. On Linux, when `platform.machine()` is not x86-64, it raises:

```
NotImplementedError: The EPANET libraries included with WNTR for Linux are built for x86-64, and this machine is aarch64. EpanetSimulator and wntr.epanet.toolkit cannot run here; WNTRSimulator can.
```

`NotImplementedError` follows the existing message for EPANET 2.0 on ARM. Windows and macOS are unchanged; the check is limited to Linux, where the problem was reported.

Related: #558 also changes `toolkit.py`, adding enums for clearer error messages. The two touch different parts of the file and merge cleanly together there. I can adapt this to #558's approach if you'd prefer.

This doesn't make EPANET run on aarch64. That needs an aarch64 library or a source build, the other options in #584. It replaces a misleading error with one that says what's wrong and what still works.

## Tests and Documentation

- **New test.** `TestLinuxMachine.test_non_x86_64_raises` in `test_epanet_toolkit.py` patches `platform.machine()`:
  - with `aarch64`, `ENepanet()` and `MSXepanet()` must raise `NotImplementedError` naming the CPU;
  - with `x86_64`, the check must pass.

  It is skipped off Linux. On `main` it fails (`NotImplementedError not raised`); with this PR it passes.
- **x86-64 Linux** (Debian 13, Python 3.13.5, gcc 14.2), CI's core selection (`pytest -m "not extensions" --doctest-modules --doctest-glob="*.rst" wntr`): `main` 470 passed, this PR 471 (the new test), the same 6 skipped. `EpanetSimulator` results are bit-identical to `main` on Net1, Net2, Net3, Net6, ky4 and ky10 and EPANET's Net1-3.
- **aarch64 Linux** (Debian 13, Neoverse-N1), CI's quick selection: the same 71 tests fail as on `main`, all of them EPANET loads. On `main`, 55 failed with the `OSError` above. The other 16 ask for EPANET 2.0 and hit the existing ARM message, because Debian's kernel name contains "arm64". With this PR all 71 fail with the `NotImplementedError` above. The new test passes.
- **Documentation:** two sentences in the installation requirements (`documentation/installation.rst`) saying which processors the included EPANET libraries are built for, and that on Linux on other processors `WNTRSimulator` works but `EpanetSimulator` doesn't.
